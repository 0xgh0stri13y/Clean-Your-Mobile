# Code of Conduct

## The short version

Be decent. This is a small project about removing unwanted software from
phones; nothing here is worth being unpleasant to anyone over.

## What is expected

- **Assume good faith.** Someone reporting that an entry broke their phone is
  helping, even if they are annoyed about it.
- **Be specific rather than dismissive.** "That rating is wrong because X broke
  on my phone" is useful. "This project is garbage" is not.
- **Accept being corrected.** This repository has already shipped ratings that
  were too generous and error messages that said nothing useful. Being wrong is
  normal; staying wrong once someone points it out is the problem.
- **Respect that people run this on their own phones.** Advice given carelessly
  here costs somebody a working device.

## What is not acceptable

- Harassment, insults, or personal attacks
- Discrimination or demeaning comments about who someone is
- Sexualised language or imagery, or unwelcome advances
- Publishing anyone's private information without permission
- Deliberately bad-faith contributions: a package entry meant to break phones,
  a change that quietly weakens the never-touch guard, or malware in any form

That last one is treated as a security matter, not a conduct one. See
[SECURITY.md](SECURITY.md).

## Where this applies

Issues, pull requests, discussions, and anywhere someone is representing the
project.

## Reporting

Report through the repository's **Security** tab if it involves private
information, or by opening an issue if it does not. If the problem is with the
maintainer, say so publicly — a project this size has no separate body to
appeal to, and that is worth being honest about rather than pretending
otherwise.

Reports will be read and acted on. Possible responses are a warning, having a
comment edited or removed, or being blocked from the repository.

## Attribution

Adapted in spirit from the [Contributor Covenant](https://www.contributor-covenant.org),
deliberately shortened. The full Covenant is the right choice for a project with
many maintainers and a real moderation process; this one has neither, and a
policy that promises machinery that does not exist is worse than a short honest
one.
